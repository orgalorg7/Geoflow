You are a senior full-stack engineer, geospatial engineer, backend architect, and product designer.

Build a production-quality MVP for a **No-Code Geospatial Analysis Platform**.

The platform should allow users with little or no GIS programming experience to upload or select an area, choose satellite data, run geospatial analyses through a graphical interface, visualize the result on an interactive map, and export the generated outputs.

The product should feel like a simplified combination of:

* Google Earth Engine
* ArcGIS
* QGIS processing tools
* Canva-style no-code workflows
* A modern SaaS dashboard

Do not build a fake frontend demo.

Build a real working system with functional APIs, database storage, background processing, raster calculations, map visualization, authentication, job tracking, and downloadable results.

# Main MVP User Flow

A user should be able to:

1. Create an account.
2. Log in.
3. Create a project.
4. Define an Area of Interest.
5. Upload GeoJSON or draw a polygon on the map.
6. Choose a satellite dataset.
7. Choose a date range.
8. Set a cloud-cover limit.
9. Select an analysis operation.
10. Start the analysis.
11. Track the processing job.
12. View the output as a map layer.
13. Change layer opacity and visualization settings.
14. View basic statistics.
15. Download the output.

## Geospatial Operations

Implement the following operations:

### NDVI

Formula:

NDVI = (NIR - Red) / (NIR + Red)

### NDWI

Formula:

NDWI = (Green - NIR) / (Green + NIR)

### NDBI

Formula:

NDBI = (SWIR - NIR) / (SWIR + NIR)

### SAVI

Formula:

SAVI = ((NIR - Red) / (NIR + Red + L)) × (1 + L)

Use a default L value of 0.5.

### True Color Composite

Use the correct red, green, and blue bands for each satellite.

### False Color Composite

Use NIR, red, and green bands.

### Change Detection

Allow the user to select:

* First date range
* Second date range
* Index type

Generate the index for both periods and subtract the first raster from the second.

### Terrain Analysis

Support uploaded DEM files and implement:

* Slope
* Aspect
* Hillshade

Terrain analysis can use uploaded GeoTIFF files in the first version.

# No-Code Workflow System

Design a workflow model that represents analysis as nodes.

Example workflow:

Satellite Source
→ Date Filter
→ Cloud Filter
→ Median Composite
→ NDVI
→ Clip to AOI
→ Export

The initial frontend does not need a fully advanced drag-and-drop editor.

For the MVP, create a guided workflow builder using forms and selectable processing steps.

However, the backend workflow representation must already use nodes and edges so a visual node editor can be added later.

Each workflow node should contain:

* id
* type
* configuration
* input references
* output references
* execution status
* validation errors

Suggested node types:

* satellite_source
* uploaded_raster
* date_filter
* cloud_filter
* median_composite
* mean_composite
* ndvi
* ndwi
* ndbi
* savi
* true_color
* false_color
* change_detection
* clip
* slope
* aspect
* hillshade
* statistics
* export

Validate workflows before execution.

Reject workflows with:

* Missing required inputs
* Unsupported node connections
* Invalid dates
* Missing AOI
* Cyclic dependencies
* Unsupported band combinations

# Important Working Rules

Before writing code:

1. Inspect the current repository.
2. Explain what already exists.
3. Identify missing components.
4. Produce a short implementation plan.
5. Start with the earliest incomplete phase.

After each phase:

1. Run tests.
2. Run linters.
3. Fix errors.
4. Show the resulting file structure.
5. Explain how to run the completed functionality.
6. List remaining limitations.
7. Continue to the next logical phase only when the current phase works.

When modifying an existing repository:

* Preserve working functionality.
* Do not rewrite unrelated files.
* Do not delete code without explaining why.
* Reuse existing conventions when they are reasonable.
* Check imports and dependency versions.
* Run migrations and tests after changes.

When you encounter ambiguity, choose the simplest architecture that supports future expansion.

Prioritize a working vertical slice:

Register
→ Create project
→ Draw AOI
→ Configure NDVI
→ Start job
→ Process Sentinel-2 data
→ Display result
→ Download GeoTIFF

This complete vertical slice is more important than implementing many incomplete operations.

Begin by inspecting the repository and creating the Phase 1 foundation. Do not create mock geospatial outputs. Every completed feature must actually work.
